# Pan Bot v1.1.6 — Parche de seguridad y estabilidad

Esta versión corrige vulnerabilidades y errores de la integración de Minecraft introducida en v1.1.5. No añade economía, rankings, eventos ni música, y no requiere migraciones nuevas (siguen siendo 4).

## Seguridad

- **Robo de la contraseña RCON / SSRF (crítico).** En v1.1.5, `/mcadmin setup host:` permitía a cualquier usuario con _Gestionar servidor_ redirigir las conexiones (y la contraseña RCON global) a un servidor propio, y usar el ping de estado para sondear puertos internos. Ahora host, puertos y contraseña salen solo del entorno; las opciones `host`, `query_port` y `rcon_port` se han eliminado y los valores antiguos guardados en la base de datos se ignoran.
- **RCON limitado a servidores de Discord autorizados.** Nueva variable `MINECRAFT_GUILD_IDS`: cualquier otro servidor de Discord donde esté el bot no puede usar RCON.
- **Se podía saltar la lista de comandos bloqueados.** `minecraft:stop`, `bukkit:reload`, `execute run stop`, `sudo … stop`, `function`, gestores de permisos y subcomandos `reload` ya no pasan, ni en la allowlist personalizada ni en modo irrestricto. Tampoco se pueden añadir a la allowlist. Los patrones de argumentos aceptan un subconjunto seguro de regex (máximo 2 cuantificadores, sin grupos cuantificados ni backreferences) para evitar ReDoS.
- **Permisos.** `/mcadmin` exige el nivel `admin` de Minecraft documentado. Si hay roles de Minecraft configurados, son restrictivos: los permisos de Discord no dan acceso alternativo. Los permisos se vuelven a comprobar al pulsar Confirmar. Gestionar roles de nivel `owner` requiere ser owner.
- **`MINECRAFT_GUILD_IDS` en todas las rutas.** Comandos, `/mcadmin` (incluido `console-mode`), botones, confirmaciones, mantenimiento y el monitor en segundo plano comprueban la autorización del servidor de Discord antes de cualquier conexión RCON.
- **Comprobación de propietario.** Ya no se compara al miembro con el ID de la aplicación. Son owners el dueño del servidor de Discord y los usuarios de la nueva variable `BOT_OWNER_IDS`.
- **Secretos.** El logger oculta los campos `password`/`token`, y la salida RCON sigue pasando por el filtro de secretos.

## Correcciones

- `/mc gamerules regla:X valor:Y` enviaba `gamerule Y Y`. Ahora la regla y el valor van por separado.
- `/mc ban` pide confirmación. Las confirmaciones solo las puede usar (o cancelar) quien las creó, ya no dependen del título del embed y las de consola se auditan, también en el canal de auditoría.
- Las respuestas se difieren (`deferReply`/`deferUpdate`) en `/mc`, `/mcadmin`, botones, selectores y modales, así que se cumple el límite de 3 s de Discord aunque el servidor esté caído o lento. Los errores tras `deferUpdate` se envían como mensaje privado y ya no sobrescriben el panel.
- Notificaciones: los avisos se agrupan (ya no se pierden entradas o salidas simultáneas); cada conexión tiene su propio identificador de sesión, así que las reconexiones dentro de la misma hora se anuncian; se usa la lista completa de `list` por RCON cuando está disponible y no se toma el `sample` del ping como lista completa; hay un margen de `MINECRAFT_OFFLINE_FAILURES` fallos seguidos antes de avisar de caída; se avisa de cada caída, no solo de la primera; y tras reiniciar el bot no se vuelve a anunciar a los jugadores que ya estaban conectados.
- `/mcadmin setup` y `/mcadmin notifications` con opciones omitidas ya no borran los canales configurados ni fallan con `NOT NULL constraint`.
- El bitfield de invitación del README era incorrecto (`1078062142` incluía **Administrator**). El valor correcto es `1101927672886`.

## Cambios incompatibles

- **RCON requiere `MINECRAFT_GUILD_IDS`.** Sin esa variable, RCON queda desactivado y solo funciona el estado público.
- Los host/puertos personalizados por servidor de Discord (v1.1.5) se ignoran: configura `MINECRAFT_HOST`, `MINECRAFT_PORT` y `MINECRAFT_RCON_PORT`.
- Si hay roles de Minecraft configurados, quien no tenga uno de ellos pierde el acceso aunque tenga permisos de Discord.
- `/mcadmin` requiere el nivel `admin` además de _Gestionar servidor_.
- Las definiciones de `/mcadmin setup` y `/mc ban` cambiaron: hay que volver a ejecutar `npm run commands:deploy`.

## Nuevas variables de entorno

| Variable                     | Por defecto | Descripción                                                             |
| ---------------------------- | ----------- | ----------------------------------------------------------------------- |
| `MINECRAFT_GUILD_IDS`        | vacío       | IDs de servidores de Discord autorizados para RCON, separados por comas |
| `MINECRAFT_OFFLINE_FAILURES` | `3`         | Comprobaciones fallidas seguidas antes de avisar "offline" (1–10)       |
| `BOT_OWNER_IDS`              | vacío       | IDs de usuario de los operadores del bot (nivel owner)                  |

## Mantenimiento

- `@types/node` alineado con Node.js 22.
- Nuevas pruebas de integración con servidores RCON/TCP falsos (robo de credenciales, SSRF, bypasses, confirmaciones y respuestas diferidas) y pruebas unitarias de permisos, confirmaciones, constructor de comandos, traducción de opciones, listas de jugadores y notificaciones.
